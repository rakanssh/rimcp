# RiMCP

Agentic intelligence for the Rim.

RiMCP is a RimWorld mod that connects MCP-compatible clients to a live colony. The mod runs inside RimWorld and hosts a token-protected HTTP endpoint on `127.0.0.1`. MCP clients use the bundled stdio proxy.

## Status

The current build focuses on colony inspection; command tools are planned.

Current tools:

- `get_colony_summary`
- `list_core_pawns`
- `get_pawn`
- `list_inventory`
- `list_bills`
- `list_alerts`
- `list_animals`
- `list_hostiles`

## Using The Mod

1. Subscribe to the mod on the Steam Workshop and enable it.
2. Open the RiMCP mod settings page.
3. Click **Copy MCP config** to copy the MCP configuration including the URL and token.
4. Configure your preferred Agentic client with MCP support.

The copied config launches the bundled MCP proxy and passes the local bridge URL plus bearer token.

If you want MCP to work while RimWorld is alt-tabbed or minimized, enable RimWorld's own **Run in background** setting. Otherwise requests will timeout when the game is not in focus.

## Connection Model

- The bridge binds to `127.0.0.1` only.
- Requests require a bearer token generated by the mod.
- RimWorld state is read or changed on the Unity main thread.

## Building From Source

Requirements:

- RimWorld 1.6
- .NET SDK

On macOS with Homebrew:

```sh
brew install --cask dotnet-sdk
```

Build the RimWorld mod DLL:

```sh
dotnet build RiMCP/Source/RiMCP.csproj -c Release \
  -p:RimWorldManagedPath="/path/to/RimWorld/RimWorldMac.app/Contents/Resources/Data/Managed"
```

Build and publish the bundled MCP proxy:

```sh
dotnet publish McpProxy/RiMCP.McpProxy.csproj \
  -c Release \
  -r osx-arm64 \
  --self-contained true \
  -p:PublishSingleFile=true \
  -p:PublishDir=../RiMCP/Tools/McpProxy/publish/
```

For local testing, copy or symlink the `RiMCP/` folder into RimWorld's `Mods/` directory.

## Development Notes

The bridge uses a background HTTP listener, but RimWorld work is queued back to the Unity main thread before execution. This keeps bridge requests out of HTTP worker threads.

The local HTTP API is currently tiny and not intended for direct use. The MCP proxy is the supported client-facing interface.
